Data Model — Onboarding / Offboarding

Midnight Ledger style, 4 new Prisma models

OnboardingTask (template definition)

model OnboardingTask {
  id          String   @id @default(cuid())
  type        String   // "ONBOARDING" | "OFFBOARDING"
  titleEn     String
  titleAr     String
  category    String   // "FORM" | "DOCUMENT" | "MANAGER_ACTION"
  roles       Role[]   // which employee roles this applies to
  order       Int
  formSchema  Json?    // Zod schema for employee-filled forms
  isRequired  Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

EmployeeOnboarding (per-instance record)

model EmployeeOnboarding {
  id              String   @id @default(cuid())
  employeeId      String
  type            String   // "ONBOARDING" | "OFFBOARDING"
  status          String   // "PENDING" | "IN_PROGRESS" | "COMPLETED" | "CANCELLED"
  startedAt       DateTime @default(now())
  completedAt     DateTime?
  notes           String?
  employee        Employee @relation(fields: [employeeId], references: [id])
  tasks           EmployeeOnboardingTask[]
}

model EmployeeOnboardingTask {
  id               String   @id @default(cuid())
  onboardingId     String
  taskTemplateId   String
  assignedTo       String   // "EMPLOYEE" | "MANAGER"
  status           String   // "PENDING" | "COMPLETED"
  completedAt      DateTime?
  completedById    String?  // User who completed it
  formData         Json?    // submitted form data
  notes            String?
  onboarding       EmployeeOnboarding @relation(fields: [onboardingId], references: [id])
  taskTemplate     OnboardingTask @relation(fields: [taskTemplateId], references: [id])
}

Onboarding: how tasks resolve

Category Assigned To Completion Trigger
FORM EMPLOYEE Form submitted → auto-complete
DOCUMENT EMPLOYEE Doc uploaded via Document module → auto-complete
MANAGER_ACTION MANAGER Manager clicks "Complete" in portal
